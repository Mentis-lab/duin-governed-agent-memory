# LongMemEval_S — DUIN vs naive-RAG, 2026-08-17

Re-run of the July baseline on current trunk (deployed `5c0d708`). Same harness, same
stratified 100-question sample, same base model on both arms (`gpt-5.5` via the OneAI
gateway), same judge. Command:

```
DUIN_ONEAI_BASE_URL=<gateway> python lme_harness.py iso --variant s --n 100 --stratify
```

## Headline

The harness defines the number as `acc(duin) − acc(naiverag)` on one base model.

| | DUIN | naive-RAG | delta |
|---|---|---|---|
| **2026-08-17** | **76.0%** [66.8, 83.3] | **85.0%** [76.7, 90.7] | **−9.0 pts** |
| 2026-07-12/13 | 74.0% [64.6, 81.6] | 88.0% [80.2, 93.0] | −14.0 pts |

95% Wilson intervals. **DUIN still loses to naive RAG.** The gap narrowed by 5 points,
but only ~2 of those came from DUIN improving (74.0 → 76.0); the other ~3 came from the
RAG arm scoring lower (88.0 → 85.0) on an unchanged design — i.e. run-to-run variance,
not progress. The two arms' intervals overlap heavily, so a single run is not decisive;
what carries weight is that **two independent runs five weeks apart both put DUIN behind,
by 14 and 9 points.**

## Per question type (today)

| type | DUIN | naive-RAG | delta |
|---|---|---|---|
| single-session-assistant | 11/11 = 100% | 10/11 = 90.9% | **+9.1** |
| single-session-user | 14/14 = 100% | 13/14 = 92.9% | **+7.1** |
| knowledge-update | 12/16 = 75.0% | 13/16 = 81.2% | −6.2 |
| temporal-reasoning | 22/26 = 84.6% | 24/26 = 92.3% | −7.7 |
| single-session-preference | 2/6 = 33.3% | 3/6 = 50.0% | −16.7 *(n=6, noise)* |
| **multi-session** | **15/27 = 55.6%** | **22/27 = 81.5%** | **−25.9** |

**This is the finding, and it is uncomfortable.** DUIN wins the two *simple single-session
recall* categories outright, and loses every category that requires assembling evidence
across sessions — including `temporal-reasoning` and `knowledge-update`, the two abilities
the bi-temporal claim/supersession machinery exists to serve. The `multi-session` collapse
(−25.9) dominates the overall gap: 27 of 100 questions, and DUIN gets barely half.

The mechanical suspect is retrieval granularity, not memory quality: the naive-RAG arm puts
BM25 top-k whole *sessions* into the prompt, while DUIN retrieves *chunks* under a slot
budget. When the haystack is ~50 sessions and the evidence is spread across several of them,
whole-session retrieval hands the reader everything it needs and chunk retrieval fragments it.
That is testable — re-run with a larger `searchK` / whole-note grounding and see whether
`multi-session` moves — and it is the obvious next experiment.

## Validity checks (both failed on earlier attempts — read before trusting any re-run)

- **Empty answers**: DUIN 1/100, RAG 0/100. An earlier attempt produced **100/100 empty** at a
  uniform ~58.5s, because `bench_instance.ps1` launches the isolated instance with a bare
  `Start-Process` that does not inherit `DUIN_ONEAI_BASE_URL`; the provider then resolves to the
  deliberately non-resolving placeholder host and every turn dies on the 60s stream-idle
  watchdog. **Always check the empty count before reading a score.**
- **Sample composition**: today's mix is `multi-session 27 / temporal-reasoning 26 /
  knowledge-update 16 / single-session-user 14 / single-session-assistant 11 /
  single-session-preference 6` — an exact match to July's, so the runs are comparable. Without
  `--stratify` the harness takes `data[offset:offset+n]` in raw file order, which yields ~100
  questions of a single type; an earlier attempt was 100% `single-session-user` (the easiest
  category) and would have flattered DUIN while testing none of its design.
- **Isolation**: bench instance ran on its own `--user-data-dir`; the operator vault pointer
  (`localBrainNotesDir`) was verified unchanged afterwards.
- **Grading**: the RAG arm's first grading pass died on an HTTP 502 from the gateway after 15
  items; the hypotheses were intact, so only grading was re-run. Partial file kept as
  `runs/iso_rag_s.jsonl.graded.partial-502`.

## What this does and does not say

It does **not** measure DUIN's actual claim. LongMemEval is synthetic conversation about
fictional personas; DUIN's thesis is fit to *one real operator's* accumulated judgment, which
this benchmark cannot express. What it does say is narrower and still worth having: on
third-party long-conversation memory QA, **DUIN's retrieval stack is currently beaten by a
naive whole-session RAG baseline on the same model**, and beaten worst on exactly the
multi-session and temporal abilities the architecture is built for.
